# Decisions

One line per choice that DESIGN.md and the milestone briefs left open. Append, do not rewrite.

- Shared package `@tg/shared` is consumed as TypeScript source (no build); files sit at the package root (`shared/config.ts`, `types.ts`, `messages.ts`, `index.ts`) and import each other with explicit `.ts` extensions so tsc, tsx, Vite and plain Node all resolve them.
- TRADING length is derived, not configured: `daysPerQuarter * ticksPerCandle` ticks; the other four phases are `config.phaseMs`. Use `phaseTicks(config, phase)` from shared, never your own arithmetic.
- Dev/e2e config override is env-based and read only by the server shell (`server/src/env.ts`): `TG_PHASE_SCALE` (scales non-trading phase ms and `daysPerQuarter`), `TG_CONFIG` (JSON deep-merge, applied after the scale), `TG_SEED`, `PORT`, `TG_CLIENT_PORT`. Vite reads `PORT` (proxy target) and `TG_CLIENT_PORT` (its own port).
- Wire additions to the DESIGN.md draft: `join` gains `role` and optional `token` (and `name` becomes optional for spectators/reconnects); new client message `start`; new server messages `welcome` (playerId, token, role, name, phase, lobby, full config), `lobby` (roster), `error` (code + message).
- `phase` message gains `totalQuarters` and `serverTime` (server clock at send time, for client clock-offset correction); `endsAt` is null in LOBBY and FINAL; `quarter` is 0 in LOBBY.
- `portfolio` gains optional `buyingPower`, `hand`, `eliminated`; `results` gains optional `final` and `awards`.
- Game-time fields on the wire (`day`, headline `ts`, `jailedUntil`) are trading days since game start (may be fractional), not wall-clock, so the sim stays free of real time.
- The welcome message carries the whole effective `GameConfig`; nothing in it is secret and the client then never disagrees with env overrides.
- New players cannot join after LOBBY (`game_in_progress`); spectators and token reconnects can join at any time.
- `config.lobby.minPlayers` defaults to 1 so a dev can start alone; set it to 2 for real games.
- Sim contract: `submit(intent)` only queues; intents are processed in arrival order at the start of the next `tick()`, including lobby intents (`add_player`, `remove_player`, `start`), so the server keeps ticking the sim at 10 Hz in LOBBY and FINAL (time does not advance there).
- Sector ids are fixed in `shared/types.ts` (`SECTORS`): tech, energy, defense, airlines, finance, health (cut from 10 on 2026-11-21: tourism, consumer, industrials and materials are gone; the headline loader skips catalog entries for sectors the game no longer has); display names are free to change.
- Other workspaces import the sim as `@tg/server/sim` (package `exports` of the server workspace).
- Root `npm run build` = typecheck everything + `vite build` of the client; the server has no build step (runs with tsx).
- Sim tick accounting: a phase of N ticks whose `phase` event comes from tick() call T ends on call T+N (which returns the next `phase` event); the tick that processes `start` only enters BRIEFING and does not consume a BRIEFING tick.
- Server derives `endsAt` from the tick clock, not from the time of sending: (wall-clock time the tick was due) + durationTicks * tickMs; if more than `net.maxCatchUpTicks` ticks are missed the surplus is dropped and a fresh `phase` message with the moved `endsAt` is broadcast.
- The initial LOBBY `phase` event of the sim is not broadcast (clients get LOBBY from `welcome`); the first `phase` message on the wire is BRIEFING.
- Lobby ghosts: a player who disconnects in LOBBY stays in the roster as `connected: false` and can reconnect by token, but their seat and name go to a newcomer who needs them, and `start` removes all disconnected players and needs `minPlayers` CONNECTED players (else `not_allowed`). After the start, disconnected players stay in the game.
- Spectator sessions are dropped on disconnect (a spectator's stale token just becomes a fresh spectator join); `maxSpectators` counts connected spectators; unnamed spectators are called "Spectator".
- A second connection joining with the same token takes over the session; the older socket is closed with ws close code 4000 (`CLOSE_REPLACED`), on which a client must NOT auto-reconnect.
- Frames over `net.maxMessageBytes` close that connection (ws code 1009) instead of getting an `error` reply; binary frames and anything else malformed get `error` `bad_message` and the connection stays open.
- Player names: control/format characters become spaces, whitespace is collapsed and trimmed, length is counted in code points, uniqueness ignores case. Player ids are `p1..`, spectator ids `s1..`.
- The game server answers `GET /health` (JSON `{ok, phase, quarter, players}`) for tooling such as the e2e script; everything else over plain HTTP is 404.
- Client: one `GameClient` (ws + store, `client/src/net`) per route; it connects eagerly (so name entry shows server reachability) but sends `join` only once it has a name, a stored session or the spectator role; the session (`{token, name}`) lives in sessionStorage under `tg.session.<role>`; any error answer to a join clears it and returns to name entry (a spectator retries once without the token); the lobby has a client-only "Change name" that forgets the token (the server keeps the old seat).
- The "replaced" close code lives in shared as `WS_CLOSE_REPLACED` (4000); on it the client stops (connection `closed`, error "seat was opened in another tab") instead of reconnecting, and a reload takes the seat back.
- `welcome` gains optional `joinUrls` (the host's LAN `/play` URLs, one per IPv4 interface); `/floor` shows the first one as "Join at" when it was itself opened through localhost, otherwise its own origin.
- `npm run e2e` (`tools/e2e/run.ts`) overrides config only through env (`PORT`, `TG_CLIENT_PORT`, `TG_SEED`, `TG_CONFIG`), runs 2 quarters of about 11 s with `minPlayers: 2`, and reads the UI through `data-testid` attributes, which are therefore part of the client's contract.
- `npm test` runs vitest through `tools/vitest.mjs`, which first switches to the real on-disk spelling of the repo path; vitest breaks on the lowercase drive letter Git Bash passes on Windows.
- `mergeConfig` validates its result (`validateConfig` in `shared/config.ts`): every leaf must have the type it has in `defaultConfig`, numbers finite and >= 0, tick/phase/lobby sizes sane; it throws a readable error, so `TG_CONFIG`, tests and the harness fail at startup. `TG_CONFIG` may not set `net.serverPort`, `net.clientPort` or `net.wsPath` (ports go through `PORT` / `TG_CLIENT_PORT`, the path is fixed) because Vite and the browser read the defaults.
- Lost tab: after the lobby, a player `join` without a valid token whose name matches (ignoring case) a player seat with NO live connection takes that seat over under a fresh token (the old token dies). A seat somebody is connected to cannot be taken this way. No password: it is a LAN party game.
- Start-time ghosts (amends the "Lobby ghosts" line): `start` only removes players who have been disconnected for at least `lobby.ghostGraceMs` (10 s); someone who reloads or blips at that moment stays in the game and can reconnect.
- Rate limit: each connection may send `net.maxMessagesPerSecond` (40) frames per fixed 1 s window; the excess is dropped unparsed and answered with ONE `error` `rate_limited` (new error code) per window. The socket is not closed.
- Roster order is join order (`p1`, `p2`, ...) and does not change when a seat is taken over.
- Client state has `replaced`: after ws close 4000 `/play` and `/floor` render only a "seat opened in another tab" screen with a Reload button (`data-testid="seat-taken"`), never a live-looking desk.
- Client timing constants live in `config.presentation` (`countdownUrgentMs`, `countdownRefreshMs`, `errorVisibleMs`); the lobby Start button counts connected players only, like the server.
- Not built in milestone 1: restart without restarting the server (FINAL is terminal; README says to restart `npm run dev`).
- Milestone 2 day convention (amends the "game-time fields" line for `tick`/`candle`/`market`): `day` is a 0-based INTEGER trading day since game start that keeps counting across quarters (day d is in quarter floor(d / daysPerQuarter) + 1; helpers `dayToQuarter`, `dayOfQuarter`, `quarterFirstDay` in `shared/market.ts`). `tick` gains `tickOfDay` (1..ticksPerCandle); fractional game time = day + tickOfDay / ticksPerCandle. Headline `ts` and `jailedUntil` stay fractional days.
- Prices move only during TRADING (one market step per sim tick of that phase) and are frozen in every other phase, so no `tick`/`candle` is emitted outside TRADING and every quarter has exactly `daysPerQuarter` candles. The last tick of a quarter comes out as `tick`, `candle`, then the EARNINGS `phase` event.
- Candle definition: built from the `ticksPerCandle` prices after each step of its day (open = price after the day's first step, close = after its last). `candle` is sent right after the day's last `tick` and is authoritative over what a client built from ticks.
- New server message `market` (`MarketMsg` = `MarketSnapshot` + `t`): public universe + all closed candles since day 0 (flat `[o,h,l,c,...]` per symbol, `unpackCandles` in shared) + latest prices + the partial candle of the day in progress. Sent to one connection right after every `welcome` (any role, any phase, also LOBBY), never broadcast. About 1 MB of JSON at the end of an 8-quarter game once rounded.
- The universe is generated when the sim is created (the seed is known before the lobby), so clients already see the symbol list in LOBBY.
- Public vs hidden universe: clients only ever get `UniverseInfo` (`SymbolInfo`: symbol, name, kind `stock|index|sector`, sector, marketCap, ceo, fund members). Betas, sigma, rate sensitivity, adv, fundamentals and fund weights stay in the sim (`Sim.getUniverse()`, never sent).
- Canonical symbol order, identical in sim, wire and client: index fund, the sector funds in `SECTORS` order, then the companies sector by sector in `SECTORS` order. The ticker field is called `symbol` everywhere.
- Fund price = fixed basket `sum(units[i] * mid(member i))`, no rebalancing; `units` are set so every fund starts at `market.fundStartPrice` with cap weights (`market.fundWeighting`: `cap` or `equal`).
- Volatilities in config are per trading day; the sim scales them by sqrt(1 / ticksPerCandle) per tick. The sim never rounds prices; the server rounds for the wire with `roundPrice` (`market.priceDecimals`, 2).
- `market.rateSensitivityMin/Max` are magnitudes (config numbers must be >= 0); the generator applies the sign (negative, finance positive).
- `market.advFractionOfCap` became a range (`advFractionOfCapMin/Max`); a fund's own adv is its members' adv times `market.fundAdvShareOfMembers`.
- All name material (company stems and suffixes per sector, CEO names, fund tickers and names) is in `server/src/sim/data/names.ts`; names and tickers are picked with the seeded RNG. Sector display names are `SECTOR_LABELS` in `shared/types.ts`.
- Sim RNG streams are forked from the root in a fixed order (universe, market; new subsystems append), so adding a subsystem does not change a seed's universe or price path.
- `MarketStepInput` (`server/src/sim/market.ts`) is the single hook for everything that bends returns later: `volMult`, `corrMult`, `dRate`, `sectorDriftPerDay`, `symbolReturn` (news ramps and price impact; on a fund ticker it moves only the fund's premium over its basket).
- Server market wiring: on every join/reconnect the socket gets `welcome`, then `market`, then the `lobby` broadcast, all in one synchronous turn between two sim ticks, so the first `tick` after a `market` is exactly (day, tickOfDay + 1) with no gap or overlap; `tick`/`candle` are rounded once and broadcast as one shared frame. No ws compression (measured: tick about 0.9 kB, candle about 3 kB, `market` 10 kB in the lobby and 1.1 MB at the end of a full 8-quarter game); `perMessageDeflate` on the `WebSocketServer` is the switch if Wi-Fi ever needs it.
- Universe character (sim-market): `market.sectorProfiles` gives each sector a centre POSITION (0..1) inside the betaMarket / betaSector / idioVol / rateSensitivity ranges; a company is drawn within +- `market.sectorProfileSpread` of it; `market.capVolTilt` makes big caps calmer; `market.rateLovingSectors` (finance) get a positive rate sensitivity. CEO names are unique per universe.
- Price step (sim-market): `corrMult` multiplies only the common factors M and S (total vol rises with it, it is not renormalised); every step draws the same normals in the same order whatever the `MarketStepInput` (one `rng.fillNormal`), so regimes, news and orders never shift a seed's underlying noise path.
- Fund premium (sim-market): fund price = basket * exp(premium); the log-premium starts at 0 and only `symbolReturn` on the fund's own ticker moves it (no built-in decay: the impact model that feeds it also feeds the decay). Unknown tickers and non-finite values in `symbolReturn` are ignored.
- Client market data is NOT in the React `GameState`: `GameClient.market` (`client/src/net/marketStore.ts`) holds universe, prices, closed candles and the live candle, with per-symbol / selection / feed subscriptions (`net/marketHooks.ts`); symbol rows and the chart write to the DOM / chart directly from those, so a 10 Hz tick causes no React render of the list (React dev mode made that 60 ms per tick). The selected symbol lives in that store and in sessionStorage (`tg.symbol.<role>`).
- Client "change %" is since the open of the current quarter's first day; between quarters it keeps showing the quarter that just ended, and before the first tick of the game it is 0.
- Chart time axis: quarter q is mapped to the fake calendar year 2000+q (one game day per calendar day) so lightweight-charts puts its strongest tick marks on quarter starts; labels are translated back to "Q2" / "D17" (`client/src/lib/chartTime.ts`). The chart frames the current quarter plus the last third of the previous one and re-frames only when a new quarter starts.
- /play desk grid is now three columns (480 px two-column symbol list | chart over headlines | 320 px side panels); in RESULTS / SHOP / FINAL the stage panel takes the list + chart area (`.desk--stage`). /floor shrinks phase + countdown to a status line once the game runs and gives the space to the index fund chart.
- Price-move cue in the symbol list is a STATIC tint of the price cell by the direction of the last tick (class changes only when the direction flips), not a fading flash: at 10 Hz the 61 fades never finished and cost a style recalculation + repaint on every frame (measured on /play in headless Edge: main thread 99% busy and 18 fps with the animation, about 25% busy and 60 fps without). Rule for later UI: no CSS animation or transition that restarts on every tick.
- Phase progress bars (/play header, /floor) are scaled with `transform: scaleX()` instead of animating `width`, so the 200 ms countdown refresh does not re-layout the page on every frame; the live price in `SymbolHeader` is its own small component (`HeaderQuote`) so a tick re-renders two spans.
- e2e for milestone 2: 2 quarters of 26 one-second days (about 63 s of game); it records every websocket frame per page and compares the DOM against them (the list must equal exactly one received tick, A and B the same tick), reads the chart canvas pixels to prove candles are painted, and measures long tasks / timer delay per page during TRADING (limits: 15% long-task time, 400 ms timer delay, a click answered within 250 ms). The chart's `data-candles` / `data-symbol` attributes are part of that contract.
- Trading lives in `server/src/sim/trading.ts` (pure, no RNG: orders never change a seed's noise path). Order qty is in shares, truncated to whole shares; an order above `leverageCap * equity` gross is CLIPPED to the largest size that fits (rejected `insufficient_buying_power` only when nothing fits); orders that only reduce a position always go through.
- Price impact per DESIGN: fill = mid * (1 + sign * lambda * notional/adv); permanent and temporary go into the NEXT market step as `symbolReturn`, temporary decays by half every `temporaryHalfLifeMs`. Each term is capped (`impact.maxSlippage`, `maxPermanent`, `maxTemporary`) so a whale order into a small cap cannot produce absurd prices. Later orders on the same tick see the earlier ones' impact (first buyer gets the best price).
- Margin call is checked after every TRADING tick: equity < `maintenanceMargin * gross` liquidates the LARGEST position (by |value|) in full, at most `trading.liquidationsPerTick` per tick. Equity < `eliminationEquity` closes everything and sets `eliminated` for good. Both checks run only while prices move (TRADING).
- Borrow fee: `shortBorrowFeePerDay * |qty| * close` per short, charged when each daily candle closes.
- Portfolio math (`valuePortfolio` in `shared/portfolio.ts`) is shared: the server enforces it and the client recomputes equity, buying power and P&L live from ticks between `portfolio` messages, which the server sends on every fill, once per trading day, at the start, and after every welcome (reconnect).
- Wire additions for trading: `fill` gains `ts` (game day) and `reason` ('margin_call' | 'elimination' when the server traded for the player); `Position` gains optional `realized` (banked P&L on that symbol). Portfolio dollar amounts are rounded to cents on the wire.
- Order entry UI: pick Buy/cover or Sell/short, then one click on a quick-size button sends a market order (% of live buying power, or a fixed $ amount from config), plus Half / Close for the held position and a close button per positions row. No confirmation step: speed is the game.
- Card catalog (design, M5 input): every card type is in `shared/data/cards.json`, with its schema, price rule and validator in `shared/cards.ts` (not yet exported from `shared/index.ts` or used by the sim). An entry is a `CardDef` plus sim-only fields: `priceMult` (multiplies the tier's `cards.priceShareOfNetWorth`, so a card's price is `max(minPrice, share * priceMult * netWorth)`), `shopWeight` (relative offer chance), `heat` (a key of `config.sec.heat`, `null` exactly when legal) and a typed `effect` (insider_tip, earnings_peek, fake_headline, event_shock, regime, lobbying, fact_check, trading_halt, sec_tip_off). Cards refer to headlines by id (regime start, during and end; lobbying stages) or by scope and direction (fake and event cards pick a matching `fake_template` / `debunk` / `event` headline). The test checks those references against the seed file. A card's magnitude sets the shock size from `news.shock`. The headline text is only matched on scope and direction. Insider and fake cards are always illegal. "Depose a Head of State" and the Sabotage and Server Meltdown events are illegal (`illegalEvent` heat). War, Pandemic, Lobbying and the other events are legal. The SEC Tip-Off targets the richest other player, because `CardDef.targetKind` has no player option. Regime drifts are first guesses for M7 to tune, e.g. war gives defense +0.3% a day, about +31% over a quarter.
- Shop (M5 groundwork, `server/src/sim/shop.ts`): one shared selection per quarter, drawn by `shopWeight` without replacement and then priced for each buyer. A shop holds at most 1 regime card, and none while `regimes.maxActive` regimes are running. Counter cards are left out unless `includeCounters` is set. Offer ids are `q<quarter>_<slot>_<defId>`.
- SEC (M5 groundwork, `server/src/sim/sec.ts`): ranks count only players still in the game, by net worth; ties keep input order, and a rank past the end of `rankMultiplier` uses its last value. A caught player is fined `fineShareOfNetWorth`, jailed from the first trading day of the next quarter (`jailedUntil` in game days), and their heat goes back to 0. A player already in jail is not rolled again; their heat, like that of anyone not caught, decays by `heatDecayPerQuarter`. The arrest wording comes from the kind of act that brought in the most heat that quarter: insider trading, spreading fake news, market manipulation, sabotage, or securities fraud.
- Regimes (M5 groundwork, `server/src/sim/regimes.ts`): active regimes become the market step input, with `volMult` and `corrMult` multiplied together and sector drifts added. Lobbying bills count against `regimes.maxActive` but do not move the market while pending. A bill that passes adds `driftIfPassed` to its sector for the rest of the game. `rateDelta` is applied once when the regime starts and reversed once when it ends. Regimes count down at the end of each quarter.
- News shocks (M4 groundwork, `server/src/sim/shocks.ts`): numbers only, no headline text. Time is the market tick (`day * ticksPerCandle + tickOfDay`), so a shock that starts near the close carries on at the next open. The move ramps over `news.rampMs` (smoothstep) up to `m * (1 + overshoot)`, then settles to exactly `m` over another `rampMs`. A revert (debunk or fact-check) goes from wherever the move is back to 0 over one `rampMs`. A market-scope shock moves every company by the same `m`, sector and stock shocks move their companies, and funds follow their members. The output is a `symbolReturn` map for `market.step`.
- Earnings (`server/src/sim/earnings.ts`): at BRIEFING every company draws `true_surprise ~ N(0, surpriseSigma)`. `leaksPerQuarter` leaks go to distinct companies, at ticks early enough to settle before the close. Each prices in 5–10% of the surprise by default, leaving the bulk of the move for earnings. The public earnings report gives each company's surprise relative to expectations. The server applies `gapFactor * (surprise - priced_in)` after a seeded 1–5 second window at the next trading open, or directly to final standings after the last quarter. Leak moves plus the gap add up to `gapFactor * surprise`.
- Headline lookup (`server/src/sim/headlines.ts`): match kind + scope + direction exactly; then magnitude + category, magnitude only, or the closest magnitude, always preferring a template not used yet. A template repeats only when every template of that kind/scope/direction was used, and then it is the one used longest ago. No match at all = the shock is skipped (no headline, no move). The headline data stays with the content team; the sim reads it through `server/src/sim/data/headlineData.ts`, and `createSim(seed, config, { headlines, placeholders })` can inject another database.
- Slots: {COMPANY} {TICKER} {CEO} {SECTOR} {RIVAL} come from the universe and the headline's target ({RIVAL} = another company of the same sector); {COUNTRY} {LEADER} {GOV_AGENCY} {CITY} {PRODUCT} come from `shared/data/placeholders.json`. One value per slot per headline; the first letter is capitalized; unknown slots are left as they are.
- News engine (`server/src/sim/news.ts`) wires the teammates' `shocks.ts` and `earnings.ts` into createSim with two new RNG streams appended after the market's (universes and price paths of a seed are unchanged). Per quarter: earnings leaks, `scheduledBeatsPerQuarter` market-wide macro beats on evenly spaced days (announced at BRIEFING by day and title, direction hidden; the first is the rate decision, which moves the policy rate by `rateStep` within the new `market.rateMin` / `rateMax`), and `randomHeadlinesPerQuarter` random headlines after `news.quietDays` (`noiseShare` neutral, the rest drawn from the new `news.scopeWeights` / `magnitudeWeights`, size jittered by `news.shockJitter`).
- One global queue for every headline (cards and regimes will use `news.enqueue`): at most one per tick and none within `news.minGapMs` of the last; items still waiting at the close are dropped. An earnings leak counts as priced in only once it is published, so leak moves plus the gap always add up to `gapFactor * surprise`.
- The server sends `briefing` after the BRIEFING phase message and `earnings` after the EARNINGS phase message. Earnings reports contain each company's symbol and surprise in an order shuffled once per quarter. Rate decisions include `headline.rate`. A join or reconnect gets the briefing, the latest earnings report, and the last `news.replayHeadlines` headlines.
- After the LAST quarter the earnings gap has no market step to land on: `sim.news.pendingGap()` holds it for the final leaderboard (M6).
- Leverage clip (M3 review): an order is clipped to the largest size with `gross <= leverageCap * (equity - this order's slippage cost)` at the effective mid, found by bisection. The size is monotone, so bisection is exact to the share. A same-side order is never cut below the current position, and an opposite-side order can at worst close it. Right after a max-size order a few percent of buying power can show as left over, because the order's own impact marks the position up.
- Balance harness (M7, `tools/balance/`): `npm run balance -- --games N --seed S --quarters Q --bots a,b --config '<json partial>' --json`. Each game seats one player per bot (`lobby.maxPlayers` is raised to fit) and plays through `createSim` with `order` intents only. Bots trade at most once per trading day, at tick 1, except the exploit probe, which trades on the last step of the game. The output is per-bot p10 / median / p90 final net worth, elimination rate, margin calls, wins, and the winner distribution against $1B–3B. It is deterministic per seed.
- Valuation at the fair price (M3 review follow-up): equity, buying power, margin calls, elimination and final net worth value positions at the mid WITHOUT the temporary impact still decaying in it (`fairPrice` in `trading.ts`). Fills still happen at the effective mid. The leverage clip counts as lost equity what the fill pays over (or gets under) the fair price. `impact.maxPermanent` is 0.06 (`kPermanent / lambda * maxSlippage`), so at the cap a whale's permanent mark-up stays below its slippage. Effect: the screen may show a position worth a little more than the server counts for a few seconds after a big order, until the temporary impact decays.
- Balance, first pass (M7, docs/BALANCE.md): `news.shock.huge` 0.5, `news.magnitudeWeights` 0.3/0.3/0.2/0.2, `news.scopeWeights` market 0.05 / sector 0.3 / stock 0.65, `market.advFractionOfCap` 0.04–0.16. Medium and large shocks are unchanged, so the scheduled market-wide beats stay calm. The base economy is aimed at a ~$600–700M winner median before cards, which are expected to carry it into $1–3B. Harness bots now receive the public headlines of each tick (`BotView.headlines`).
- Cards in play (`server/src/sim/cardEngine.ts`) wire julien's shop.ts, sec.ts, regimes.ts and the catalog into createSim with three new RNG streams appended after the news ones (shop, SEC, regimes). Buying: SHOP only, one buy per offer, hand limit `cards.handLimit`, refused if paying would leave equity below `economy.eliminationEquity`; the price comes out of cash. Playing: TRADING only, not while jailed or eliminated. The last quarter's shop is empty (no quarter left to play in).
- Card targets on the wire: `play_card.target` is a stock symbol for stock cards; for sector cards a sector id, or any stock or sector fund of that sector. The client plays a card on the symbol selected in the market list.
- Insider tip = the next real (engine) headline in the queue that fits the card's focus is rendered NOW (template and slots fixed) and sent privately as `headline` with `early: true` at least `leadMult * cards.insiderLeadMs` before it is published to everyone, with the same words. No such headline coming = the play is refused and the card is kept. Boardroom Mole = a private early note with the stock's true surprise.
- Fake headline = a `fake_template` headline and move now; news.ts queues a `debunk` headline after `cards.fakeDebunk{Min,Max}Ms` that reverts the move when it is published. Debunks and regime-end headlines that miss the close are published first thing next quarter (`carry`). Due card and regime headlines go before any backlog of engine headlines (still one per `news.minGapMs`).
- Regime and lobbying cards: startRegime + the start headline now, the "during" headlines spread over the rest of the current quarter, a `moment` (kind regime) for the projector; the market step gets the regimes' volMult / corrMult / sector drifts every tick and their rateDelta once. Regimes count down at RESULTS; their end headlines go out at the next open. Counter cards (stretch) are not offered and are refused if played.
- Heat: an illegal card's heat on play; `tradeManipulatedTarget` heat once per stock per quarter for trading a stock (or a fund of a sector) you hit with a fake or an illegal event card that quarter. The SEC rolls at RESULTS (sec.ts): fine out of cash, `jailedUntil` = first day of next quarter + jail days; jailed players cannot trade or play cards, positions stay open. An arrest of the richest player is a `moment` (kind arrest). At most `presentation.maxMomentsPerGame` moments per game.
- `portfolio` now always carries `hand`, `heat` and `jailedUntil`. RESULTS emits a basic `results` event (leaderboard by net worth, statements with card spend and fines, arrests, card authors in `recap.cardAuthors`, empty `recap.topMoves`); the recap moves, awards and the results / final / floor screens are M6.
- Results (M6, `server/src/sim/results.ts`): a "trade" is one symbol over one quarter, with `pnl = end qty * end price - start qty * start price - sum(fill qty * fill price)`, at market prices and without fees. The recap takes the 3 largest quarter moves among sector funds and stocks, at most one per sector. Each move's cause is the published item (or earnings gap) with the same sign that contributed the most log-move: a market headline counts in full, and a stock headline counts by the stock's weight for a sector move. If that cause explains less than 25% of the move, the cause is "noise". Earnings gaps explain the quarter they land in (the next one). Awards are only given when the data supports them, and one trade can't win both Best trade and Best short.
